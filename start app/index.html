Folder access

      Programs & desktop

      i

      Search installed Nix programs by name or path. Selecting a suggestion does not grant access until you click Add program.

      Required sandbox bundles are listed after OMBP's first build and remembered. Revoking one blocks its primary Nix store roots and can break OMBP; already loaded code cannot be taken back. Restore it here if needed. Private folder changes require a new launch.

      A nested Wayland compositor separates OMBP from host screen/input protocols. No host display socket, X11, session bus, portals, Podman socket or host program execution. This is not host-desktop automation.

      This is a host-resource whitelist, not a ban on arbitrary code inside the container. GPU and display changes require a new launch. GPU selection is detected at UI startup; manual overrides are kept.

          Websites & internet

          i

          Every subpath is allowed. Subdomains are allowed by default over http or https (a leading www. is ignored); untick Subdomains for exactly the listed origin. Auto-approve: "google.com" lets through any host containing "google" and ending in ".com" (such as update.googleapis.com, but also look-alikes); an entry without a dot matches any host containing it. Settings edits that list. Private networks and direct connections are blocked. HTTPS is inspected using this launcher's local CA; clients must trust it. WebSockets work to allowed sites; certificate-pinned clients fail closed.

          Optional host-side Authorization injection keeps the stored header outside the container and is sent only to the exact origin. Store it using secret-tool store --label='OMBP API' application ombp-start origin https://api.example.com, then enter the complete header value at its prompt (for example Bearer …). Trust that origin: its responses could echo the credential. Otherwise use the container's private keyring; the AI can read credentials there.
