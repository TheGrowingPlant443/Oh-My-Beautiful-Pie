OMBP Start app

One container. Permissions you control outside the AI.

Connecting…

Container mode: OMBP and every OMP child run together. Only approved host resources are exposed. Network requests must pass the website gateway.

Folder access

Host folders appear at /host/…. Grant a vault directory for Obsidian files; this does not control the host Obsidian app.

    Read-only by default. Grants include subfolders. Host symlinks, hardlinked files, special files and launcher state are blocked. Broad grants can expose secrets.

    Programs & desktop

    Make an installed Nix program available inside the container, including its runtime dependencies.

      A nested Wayland compositor separates OMBP from host screen/input protocols. No host display socket, X11, session bus, portals, Podman socket or host program execution. This is not host-desktop automation.

      Programs already bundled with OMBP and interpreters remain runnable. This list controls host mounts, not arbitrary code execution. GPU and display changes require a new launch.

      Websites & internet

        Exact scheme, host and port; every subpath is allowed. Subdomains need separate entries. Private networks and direct connections are blocked. HTTPS is inspected using this launcher's local CA; clients must trust it. Certificate-pinned clients and WebSockets fail closed.

        Optional host-side Authorization injection keeps the stored header outside the container. Store it using secret-tool store --label='OMBP API' application ombp-start origin https://api.example.com, then enter the complete header value at its prompt (for example Bearer …). Trust that origin: its responses could echo the credential. Otherwise use the container's private keyring; the AI can read credentials there.

        Denied attempts

        Gateway-observed website, folder and program attempts. Use + to grant access without restarting.

        Latest 500 distinct denied resources, with counts. Direct network syscalls and missing programs outside the gateways cannot be identified here. Revocation cannot undo data already read or code already loaded.

        Permissions apply live in container mode only. State and logs stay on the host. This launcher does not modify OMBP.
